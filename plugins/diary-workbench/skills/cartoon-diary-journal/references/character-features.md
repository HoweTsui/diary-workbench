# 从照片提取角色特征

新人物、旧人物校准或用户修改外观时读取本页；母版画法仍以 `style-contract.md` 为准。图片在 `assets/style-reference/`，references 存规则和索引，不要求图片也放在 references。

## 看什么、怎样画

头发用疏朗但足以辨认的线条表达，内部留白，不整片涂黑、不画密集发丝，与脸部轮廓保留断开。长发、马尾、卷发保留长度、分缝和扎发位置。已确认参考为 `assets/style-reference/character-features-v1/feature-sheet-approved-v2.png`，与默认母版为同一张12人图；早期草稿不再作为生图参考。

先逐个角色查看本次照片，用 `characters[].anchors` 记录可见特征；角色ID、照片路径、观察特征、线稿表达和未知部分合并记录在同一 brief/run 中，不另外生成一份 appearance-map.json。只记录外观，不从照片猜姓名、关系、性格或职业。

| 照片里的特征 | 黑白日记画法 | 不可做的替换 |
| --- | --- | --- |
| 发长、发量、分缝方向、刘海 | 保留总体轮廓与发际线；少量线条交代发束 | 所有人都变成母版的短黑发 |
| 卷发、波浪、蓬松度 | 少量连续曲线表达轮廓，不画写实发丝 | 为省事改成直发 |
| 高/低马尾、丸子头、辫子 | 保留扎发位置、方向与发尾长度 | 改成散发或复制示例角色 |
| 圆框/方框眼镜 | 镜框、镜桥和镜腿用统一线宽；框内保留圆点眼 | 增加照片中没有的眼镜，或用镜片代替眼睛 |
| 脸部轮廓、下颌、耳朵、胡须 | 在母版结构及 geometry 容差内保留可识别差异，胡须仅在确实可见时简化 | 靠夸大鼻子或丑化面部区分角色 |
| 衣领、袖长、衣着、配饰 | 保留本次指定或确认的身份锚点；颜色改为线条/留白区分 | 擅自新增装饰或把当天服装当成永恒身份 |
| 宠物耳形、耳尾姿态、花纹 | 保留能辨认的轮廓与关键小色块；细腿和爪掌按物种母版 | 猫狗互换、改变品种特征或用大黑块涂满身体 |

眼型照片即使狭长，也转换为当前母版的正圆豆豆眼；真实身份差异主要由轮廓、发型、眼镜等共同表达。鼻子可在既有数值容差内保留轻微差异，但开放 C 形、鼻根断口、端点位于双眼中心垂线之间不变。不得为了模仿新参考图而回退旧鼻型。用户明确改变这些结构时另做新母版预览。

遮挡、模糊或没有拍到的特征标为“未知”，不补造；缺失会影响辨识时再问用户。多照片冲突以用户说明和当前确认版本为准。人物卡同时展示全身、面部细节与简短特征核对清单，用户确认后写入图谱 profile.appearance。

## 特征图的用途与状态

`assets/style-reference/character-features-v1/library.json` 索引用户已确认的12人样貌及体形参考，包含正圆脸基型与扩展类型、线条发型、眼镜、简化胡须、瘦身与腹部轮廓。这里只提供画法，不提供用户身份；母版自动作为第一张图片实际附给工具，无需再次手动添加。

扩展索引 `assets/style-reference/character-extension-v1/library.json` 将参考分工并强制实际附图：每次出现 human 的 onboarding、expression、diary 请求，都附 `appearance-variants.png`（发型、衣服、配饰多样性）、`age-proportions.png`（用户信息/参考所示年龄阶段的相对比例）和 `age-variety-example-v2.png`（开放式脸型、年龄呈现与体型组件示例）；并附已确认的 24 种表情图 `assets/style-reference/style-lock-v1/human-expression-reference-v6.png`。这几张图按角色范围随场景过滤，必须逐张按组件用途使用，不是只在提示词里提到。后者虽为历史草稿，但用户已指定作为组件参考；它不是六种固定角色或角色数量上限，也不代表审批了其中的角色整体。旧 `expression-draft-v2.png` 不使用。`human-expression-reference-v6.png` 的名称和表达由同目录 `library.json` 的 `expressionVocabulary` 定义。批准母版仍唯一锁定画法；`feature-sheet-approved-v2.png` 与母版哈希相同，不重复附图。组件参考中的任何角色都不是用户身份模板；详见 `references/identity-fidelity.md`。

人物必须有一处小面积纯黑主色块（现有衣物、配饰或小发束之一）；优先复用本人确认卡中的分配，不把眼珠/口腔/细小图案算主色块。旧卡全白时只转译原有衣物/配饰的黑白分配，不能新增服装或身份特征；新卡经用户确认后保持跨场景稳定。用 characters[].blackFill 可显式记录 area 和 basis，未填写的旧brief沿用确认卡/现有衣物转译规则，不增设补问。具体面积边界见 style-contract.md：逐角色目标≤20%、硬上限30%，不以整页留白稀释。外观类型仍靠多个真实可见锚点组合，不能把整头发或整套衣服都涂黑，也不能新增眼镜、胡须或配饰来凑黑量。动物只保留真实花纹和鼻子，不强加人物主色块。

## 体形与年龄

在 characters 中记录用户说明的 `ageGroup: child/adolescent/adult/unknown`，未说明实际年龄即 unknown；成年人的 `ageStage` 可进一步写 `young-adult/middle-aged/older-adult`，只有用户明确提供才填写。可记录 `bodyType: slender/regular/full`。若上传的是绘制角色，保留图片明确呈现的年龄与体型观感，但不将其解释为真实年龄事实。年龄比例图与开放式年龄/体型示例每次 human 生图都必须实际附上，分别只校准相对身高/头身比例和年龄、脸型、体型组件；不可替代角色本人的身份图或 `geometry.json` 画法基线，也不能将成人缩成儿童体形。geometry 中躯干尺寸为 regular 基线；选择 bodyProfiles 对应的 torsoWidth，四肢线宽不随体形变粗。较胖者在衣服前缘画出腹部曲线，不靠肥下巴表达。

`chestContour` 默认 neutral。仅用户说明为成年女性且外观支持时采用 subtle-clothed，表现为覆盖衣服的轻微外轮廓起伏；儿童、青少年及年龄未知一律 neutral，不以照片推断发育阶段。年龄信息与外观依据记录在同一 brief/run 中，不把示例人物的年龄复制给用户。

头直接接身子但用下颌/领口线分开，不出现独立细脖，也不融合成一个轮廓。身体始终侧向，远侧手仅在动作需要时露出。耳朵在脸部皮肤边界最外侧；下巴末端不越到耳后。

景物也须按用户照片或描述保留标志性形状、物品与相对位置，再简化纹理和非必要背景；不能为了套模板改成无关房间、建筑或道具。

用户搜集的关系图只参考不同人物的外观表达，不采集其关系箭头、姓名或原作品人物身份；上传原图留在本地任务材料，不复制成公开 Skill 的人物图谱。普通用户的照片始终只进入其个人归档。
