# 生成与交付检查

## 生图前

- validate_brief 默认校验并附上已确认母版，独立于实验模板状态。旧参考包不参与新任务。
- 每个含 human 的任务都必须实际附上 identity-fidelity.md 列出的全部角色组件图，并按 `characterIds` 过滤；每个角色须有自己的来源图/身份卡。逐场导出 --request-output，实际调用使用其中的全部 referenced_image_paths，母版第一张。保存请求和生成结果路径；文件存在不等于工具收到图片。
- 用户身份来自本次角色卡；旧卡需要按母版校准。预览可用草稿卡，正式必须用户确认且 identity.styleVersion 与母版版本相同。
- 每次一个清楚动作，不让模型生成三连画。全部场景照片主要内容须有 photoCoverage/事件映射与海报落点，再用 posterRows 完整合成最多5行，不能只选5张；正文保留完整原文。相同事实可合并，不同事件不伪造成同时发生，细则见 photo-integration.md。
- 参考附件超限自动合板，不让用户删照片或确认合板；母版首张独立，核对实际 request 与来源清单。辨识基于画风约束，不要求保留每根发丝、写实纹理或参考整个人物。

## 出图后实际查看

onboarding 人物卡逐角色核对：仅一个完整半侧面全身及一个同朝向头脸细节。多角度、重复全身、缺少头脸细节或混入参考示例人物均不通过；不能裁掉错误视角后冒充合格卡。

逐个角色核对 style-contract.md：双眼可见侧向结构、正圆豆豆眼、鼻根端点处于双眼垂线范围、鼻根断口、低位偏耳侧嘴、细双线白色肢体。猫狗鼻子不省略、细腿和大爪、轮廓光滑。所有人物与动物的头部、身体必须侧向；任何正面或背面角色均判定不通过，不以原图朝向或事件为例外。

人类角色逐一与对应上传图/确认身份卡、批准母版、外观/年龄体型组件图和目标表情对照：脸型、发型、年龄观感、体型、服饰锚点及表情语义不得错配或遗漏；不接受多出/少掉眼睛、参考表情眼睛混搭、眼白发灰、参考角色整体移植。任一可辨认偏差即 FAIL，修正后重看；达不到就报告未通过，不交付成“已通过”。逐角色写入 `qa-checklist.md` 的结论。完整零容差规则见 `identity-fidelity.md`。

逐场检查完整头脚耳尾与道具、透明边、自然结束的背景线。不接受漫画框、整片房间背景、无边框矩形裁断、整齐截断的地板/墙线。将单场景完整等比合成，不硬裁、不把白底去成透明、不贴白板遮掩。

逐角色检查本人主黑块实际存在且跨场景位置一致，不用眼珠/口腔/细小图案充数；面积核对分离角色与整页，≤20%为目标、30%为硬上限。动物不为了比例新增花斑。对每个可见上臂、前臂、大腿、小腿的直段按同一头宽基准比较，坐姿/盘腿/抱宠物也必须同宽细双线；不缩手鞋补救，不加粗描边掩盖。

放大检查头发、面部、衣褶、关节和道具各开放端点：同线宽半圆收口，没有渐细尖尾、三角笔锋、方头或重复线。非人物/动物道具只保留必要外形和少量结构，逐物检查杯子网格、篮子编织、食物点阵和密集褶皱；任一非必要纹理即不通过。局部细节断点允许，但断口两端同样圆头，头脸及关键结构不能被截断。

人物与道具内部应为不透明白色，纸张横线只穿过外围透明区域和备注区。纸张和悠哉文字由本地生成；一条备注对准实际墨迹中心。顶部和右侧没有插画越界、竖分隔线和不透明说明面板。

## 三项独立结论

1. 结构：输入schema、文件/哈希、身份批准、角色ID、日期、选景与文字长度；preflight 只报告结构结果。
2. 图像技术：透明边/完整边界、3:4尺寸、字体可用、整页与独立角色分别检查黑色实墨目标≤20%硬上限30%、除浅青横线外无装饰色、正常平滑抗锯齿。独立透明角色可用 --character 检查；它不自动分割场景、不识别主色块或鉴定线端/四肢，仍需目视。
3. 人工视觉：实际对照母版检查上述五官和场景自然留白，在桌面及窄屏查看最终 PNG。前两项通过不能代替此项；未查看不能写视觉通过。

局部缺陷可有针对性修正，并保留其余身份与构图。没有自动评分、择优或评审驱动的循环重生。用户未确认新角色或海报时保留草稿，不替换正式资产。日记正文与照片验收继续按 diary-document.md 和 qa-checklist.md。
