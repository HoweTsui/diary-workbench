# 全部照片整合与工具附件

全部场景照片参与海报，主要内容整合进同一张 3:4 海报的最多 5 行；禁止因超过 5 张而自动选择局部、将其余照片仅归档。行数、独立插画数和工具附件数是三个不同数量。

## 内容归组

逐张看图，记录出镜角色、主要事件/动作、对应表情与关键物件。相同事件的重复、互补照片可融合为一个自然场景；每张来源仍有对应落点，独有主要内容不得丢失。不同时空或不同动作使用独立插画，再放入同一行，不虚构同时发生。每次生图仍是一个清楚动作、透明外部的独立插画，不生成整页、照片拼贴或三连漫画框。

按明确事件时间组织阅读顺序；未知时间沿用上传顺序，不猜测。先合并重复动作、共用必要道具并简化非必要细节来控制密度，不裁人物、不拉伸、不缩小既定文字。背景自然留白，人物/动物侧向、等粗圆头线条、细四肢、原有手鞋/爪大小、五官和对应表情约束不变。

全部原照片继续按上传顺序保留在正文三列宫格与原件归档。正文有全部照片不代表海报已覆盖主要内容，两项分别验收。身份来源、母版及组件图是参考，不当成需要在海报中逐张展示的事件。

## brief 的记录

保留 schemaVersion 2。`events` 表示逐次生成的独立插画，不再等同于行数；日记超过 5 个 events 时必须有 `posterRows`。未提供分组的旧 1–5 场景 brief 保持一场一行。

`posterRows` 为 1–5 个对象，每项包含 `eventIndices`（从 1 开始）和 `caption`（4–10 字）。所有事件按已编写的阅读顺序恰好出现一次，不能漏、重复或自动舍弃；右侧一条行备注对齐这一行实际墨迹中心。

场景参考超过 5 张时，`photoCoverage` 必填，覆盖全部 `role=scene` 的 ID；较少照片也建议记录。每项包含 `referenceId`、`keyContent`（主要内容字符串列表）和 `eventIndices`。后者必须与事件的 `referenceIds` 一致；一幅插画可以引用多张同事件照片，同一照片也可明确用于多个不同插画。只列 ID 不算语义覆盖，最终须逐张对照实际画面。

示例片段：15 张同类事件照片可归入 5 个插画，每个引用 3 张来源；15 个不同动作则分别生成 15 个插画，编入最多 5 行。如何归组由看图后的事件语义决定，不机械要求每行 3 幅。

```json
{
  "posterRows": [
    {"eventIndices": [1, 2, 3], "caption": "上午出门散步"},
    {"eventIndices": [4, 5, 6], "caption": "午后整理房间"}
  ],
  "photoCoverage": [
    {"referenceId": "photo-01", "keyContent": ["阿豪牵猫包出门"], "eventIndices": [1]},
    {"referenceId": "photo-02", "keyContent": ["同次出门，猫包上的小挂件"], "eventIndices": [1]}
  ]
}
```

这是字段片段，不是完整 brief；需补齐所有 events、references 和全部来源记录，不能仅复制示例两张。

## 自动附件打包

使用 `build_diary_prompt.py --scene N --request-output request-N.json` 导出实际调用参数。CLI 默认附件预算为 5，可用 `--max-reference-images` 对应工具实际限制；这不是照片上限。生成前自动打包，无需用户确认合板或删照片。

母版始终为第一张独立附件，其余相关身份、组件、表情、物种与场景来源按职责制作参考板。每张来源完整等比显示，不裁切、不拉伸；板上用 R 编号标识，提示词说明各来源的用途与角色。每格默认 1200px，最低 1024px；实际看不清规范或身份锚点时增加 `--reference-tile-edge`，不能把低清缩略图当作合格参考。

输出 `request-N-references/manifest.json` 保存全部来源路径、哈希、职责、角色范围、板内位置、缩放和实际请求哈希；脚本验证数量、覆盖和板内来源像素。原始参考不改，不批准新母版。相同请求可重复导出并复用已校验参考板；来源、参数或预算变化时使用新的 request 文件名，不覆盖旧证据。

工具仍因数量拒绝时，按实际限制自动重建新版本请求并重试；不重复发送相同超限参数，不将数量限制交给用户解决。若重建后仍因其他实际错误失败，报告具体错误，不删除必需来源或伪造成功。

```bash
python3 scripts/preflight_check.py --brief brief.json --preview --requests request-01.json request-02.json
python3 scripts/build_diary_template.py --scenes scene-01.png scene-02.png --config brief.json --output-dir poster-v1
```

`--scenes` 按全部 events 的顺序提供独立透明插画；`posterRows` 决定分组。分组任务不用整张图片切行，避免截掉头像或混入相邻行。程序证明结构、来源与文件一致，不代替工具实际调用和最终人工视觉验收。

## 风格内的可辨识

母版锁定画法，角色自己的来源锁定必要身份锚点，组件图锁定对应局部表现，表情图锁定情绪语义。输出可辨识必须建立在这些画风约束上，不要求保留每根发丝、写实毛发、衣料纹理、摄影光影或背景全部细节，也不照搬示例角色整体。允许风格化简化，禁止借简化换脸、错配发型/体型/年龄呈现、遗漏关键物件或改变情绪。参考附件完整显示与成图细节取舍不可混淆。
