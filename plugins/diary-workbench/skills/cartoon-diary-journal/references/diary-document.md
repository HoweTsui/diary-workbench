# 日记正文入库

保存目标、实际工具回读和同步到对应 3D 日记本的收尾要求见 `task-delivery.md`。两端均为正式交付项，不能只导出本地示例文档或仅更新书籍清单。

日记文档按实际日期命名 `YYYY-MM-DD`（Markdown 为 `.md`），正文依次包含日记内容、完整海报、全部原照片的三列宫格。已有文档保留其他内容，在对应位置补充，不能重复创建当天日记。Markdown 构建器只替换自己带日期标记的区域；既有未标记正文需 Agent 先人工合并到 body，核对后再入库，不能盲目重复追加。

海报最多5行不限制照片数；全部场景照片主要内容均整合到海报，全部原照片仍展示与归档。正文照片齐全不能替代海报内容覆盖，分别对照 photoCoverage、posterRows 和实际图像，见 photo-integration.md。

## 文案保真

正文允许轻润色语序、错别字、标点，但人物、时间、事件、因果、否定、情绪强度和用户立场必须不变。原文逐字保留在 sourceText。标题、备注和场景逐条对照原文，禁止新增情节、评价、夸张或升华；选景不能省掉改变含义的限定。字数不够时调整表达和选景，不可牺牲原意。

例如原文“上午没去跑步，因为下雨，有点失落。晚上只散步十分钟，并没有开心起来。”可轻润色标点；不可改成“雨中坚持跑步”“散步治愈了我”。分别核对否定、原因、先后、十分钟和情绪未变，不以关键词匹配声称语义通过。

## 图像及工具适配

先用悠哉文字层完成日期、标题、每场备注，导出完整 PNG；无字插画或只有 HTML 不是最终海报。保留高清 PNG，正文版默认长边 2048px，不放大小图，不做有损量化。照片保留原件，正文使用压缩件；按输入顺序三列排列、保持比例不裁切，最后一行可不足三张。照片不受插画黑白配色约束。

原件保持原名；正文附件使用日期及序号，如 `YYYY-MM-DD-海报.png`、`YYYY-MM-DD-照片-001.jpg`。压缩后必须重新解码、检查实际尺寸与方向，并与原图比较，异常变黑/空白/失真就重试，仍失败则停在草稿并说明哪张失败；暗光原图不按亮度一刀切。

工具支持原生三列图片时使用原生布局；否则嵌入三列宫格图片，同时保留全部单张附件和原件。Markdown 使用 `![说明](持久附件路径)`；Obsidian 可使用其附件嵌入语法；文档平台须上传图片并插入原生图片块，不把本机 file 路径写到云文档。使用目标工具实际预览，检查所有图片可见及顺序，不以链接存在代替验收。

## 本地导出

文字合成时可在 `scripts/build_diary_text_layer.py` 命令增加 `--poster-png <新PNG路径>`，导出带日期、标题和备注的完整 PNG。使用无文字插画及已检查的场景坐标；导出后仍须核对实际字体、图文对齐和边界。

脚本依赖 Pillow（缺失时安装 `python3 -m pip install Pillow`；支持的 HEIC 解码器缺失时先用平台工具转换并核对原图，禁止静默跳过）。

`scripts/build_diary_document.py input.json --output-dir <日记目录>` 接受 JSON：date、sourceText、轻润色后的 body、title、events（caption）、poster（已合成完整 PNG 路径）、photoArchive（归档清单路径）。路径相对 JSON。清单 schemaVersion 1 保持兼容，新增 order 和 validation；旧清单以数组顺序为准，导出时重新检查压缩结果。

输出日期命名的 Markdown、HTML 预览、持久附件、高清海报、压缩海报、原件、单张照片与宫格。HTML 使用三列原图布局，Markdown 使用通用宫格图片。source.json 保留逐字原文，review.json 留作人工语义及视觉核对，脚本不能将其自动标记通过。HTML 是同批附件预览，不替代用户最终笔记工具的预览验收。
