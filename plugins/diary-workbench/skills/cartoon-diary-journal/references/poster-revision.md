# 修改已有海报与补充元素

适用于旧日记补画、添加人物/动物/道具、替换局部和用户要求转换画风。不是另一套简化生图流程，不能跳过当前母版、角色身份与物种参考。用户要求修改目标海报即授权该范围内的修改；“不擅自重画历史日记”只保护未请求修改的日期/场景，不豁免目标场景的画风要求。

1. 保留旧海报原件，读取原始 brief、场景图与排版配置；记录目标日期、目标场景、要增改的内容及明确不得改变的内容。缺失源文件时先根据原图恢复可核对的场景与文字，不猜测缺失事实。
2. 将旧海报/目标场景放入 `references`，设 `role: scene` 和唯一 `id`，由对应事件的 `referenceIds` 显式引用。旧图只提供内容、动作和构图，不得标成 style、identity-approved 或替代真实角色卡。所有目标场景中出镜的旧角色和新增角色均列入 characters；各自附身份参考。
3. 必须使用 `build_diary_prompt.py --scene N --request-output ...` 导出并实际调用 ImageGen。当前母版、人物组件参考、对应猫/狗物种参考、逐角色身份图必须真实随请求发送，不能只在提示词写路径。猫狗不套用人类鼻型、发型、手脚或整张人类表情；表情语义按事件分别转换为物种相应的眼嘴结构。
4. 对请求修改的场景统一转换既有和新增人物/动物的画法，不保留旧画风主体再拼贴新角色。身份、年龄呈现、体型、花纹及事件不变；统一等粗圆头线、白色内部、当前脸型与物种结构。若用户明确锁定某个局部不得修改，遵守锁定，不擅自扩大重绘范围；真实冲突须说明。
5. 新场景保持完整头顶、耳、脚、尾和透明安全边；不重生成整页文字。通过本地排版替换目标场景，保留其他场景、原文、标题、日期、备注和原照片。不要硬裁、全白抠图或用白块遮盖旧元素。
6. 实际查看输出与参考并排对照，分别核对每个人物和每只动物：身份锚点、年龄/体型、五官/耳鼻/尾、表情、线宽圆头、白填充、完整边缘；同时核对未修改场景与文字。任何可见画风偏离即不通过，不能以“基本相似”交付。脚本通过只证明附件完整，不证明图像已达标。

仅当角色专属组件已确认、符合当前物种参考和画风且动作匹配时才能直接复用；旧组件的批准记录不能豁免当前画风检查。记录新请求、实际调用、输出与核验结果，按既有交付流程更新对应日期，不能仅更新预览而宣称入库。
