## 在 Codex 使用

1. 解压完整发布包，保留 `marketplace/.agents/plugins/marketplace.json` 和 `marketplace/plugins/diary-workbench/` 的相对位置。
2. 在终端运行 `codex plugin marketplace add /绝对路径/marketplace`。
3. 在桌面应用的插件目录选择「日记工作台 · 本地测试」，安装「日记工作台」。需要时重新打开应用，在新对话中说「打开日记工作台」。

安装后的 Skill 启动本地服务，并用 Codex 内置浏览器在右侧打开工作台。不是通过清单自动注入一个原生侧边栏，也不是已发布到公共插件目录的在线服务。

手动验证可在插件目录运行 `node scripts/start.mjs`，访问 `http://127.0.0.1:8185/`。需要 Node.js 22+、npm、本机已登录的 Codex、Python 3 和 Pillow。首次启动会运行 `npm ci`。Python 可通过 `DIARY_PYTHON` 指定；Codex 可通过 `DIARY_CODEX_PATH` 指定。不会转用付费 API-key 通道。

默认私有数据保存在用户数据目录的 `diary-workbench-default`，不在插件缓存中；可用 `DIARY_WORKBENCH_DATA` 指定位置。默认端口可用 `DIARY_WORKBENCH_PORT` 指定。不要把这个私有目录提交 GitHub。

## 状态与边界

- 0.1.1 同步工作台交互修复：原页图片放大、顶部返回编辑、线性展开箭头、正在填写标签，以及 HEIC/HEIF 等图片的本地预览。原文件不覆盖；无 MIME 的图片按扩展名识别。macOS 使用内置 ImageIO 解码，其他系统需 Pillow 及相应格式插件（HEIC/HEIF 需 pillow-heif）；无法解码时保留原件并显示重试。系统剪贴板必须实际提供图片文件，多张粘贴取决于来源应用。

- 这是本地安装测试版，不等于完成公共目录发布或真实日记生成验收。
- 默认阅读器使用现有引擎，空白库不把任何样例海报当成你的日记。新用户身份需要按输入建立，不使用风格示例替代。
- 连接已有 Obsidian 库仍需核实原日记本/图谱格式并配置私有 `workspace.json`；没有做“任意目录一键迁移”的承诺。
- 历史海报转画风尚未执行。以后只新增版本，原海报、原文、原照片和 Markdown 结构保留；原嵌图与阅读器版本不自动替换。
